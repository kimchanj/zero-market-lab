# TIGER V2 Research Workstation — 현재 버전 안정화

## 사용과 실행 경계

`experiments/tiger_etf_v2/build_simulation.py`로 실제 360750 OHLCV 기반 로컬 payload를 만든 뒤
`scripts/run_research_ui.py`를 실행하고 `http://127.0.0.1:8062/tiger_etf_v2/`에서 확인한다.
기존 8061 정적 화면은 서버 재계산 API가 없으므로 투자조건 변경용 화면이 아니다.
원시 데이터와 생성 산출물은 Git에서 제외된다. 최신 데이터는 공급자에서 별도로 수집해야 한다.

화면은 투자조건 → 결과요약 → 일별 매매복기 → 금융차트 → 뉴스/연구 → 기술 상세의 여섯 접이식
영역이다. 앞 네 영역은 기본 펼침, 뒤 두 영역은 기본 접힘이다. 매매복기 기본 표에는 날짜, OHLC,
한글 상태/행동, 체결가, 수량, 현금, 총자산, 익절 목표, 보유일, 한 줄 설명만 표시한다.
가격·회계·DecisionRecord·reason code는 행의 상세보기 안에서 확인한다.

입력 필드는 시작일, 종료일, 초기금액, 시가 대비 매수 지정가 %, 매수가 대비 익절 %, 최소 순수익 %다.
기본 입력 기간은 한국시간 현재 연도의 1월 1일~오늘이다. 1·3·6·12개월은 한국시간 오늘에서
달력상 기간을 역산하며 월말은 해당 월의 마지막 날로 맞춘다. 전체는 보유 데이터의 첫 관측일부터
오늘까지 입력한다. 직접입력은 사용자가 날짜를 지정한다. 이 버튼들은 **투자기간 입력**을 변경한다.
실행 버튼을 누르기 전까지 기존 결과를
유지하고 변경 대기 상태를 명시한다. 실행하면 Python generic engine이 선택 기간의 OHLCV를 필터링해
처음부터 재계산한다. Summary, Ledger, Trade, marker, 평균단가, 익절선, 연구 기본기간은 반환된
run ID에 묶는다. 차트의 1M~ALL은 표시 범위만 바꾸고 전략 계산에는 영향을 주지 않는다.

금융차트에서 날짜별 Crosshair를 움직이면 가격 OHLC·등락률·거래량 아래의 작은 매매복기 영역이
같은 날짜의 Daily Ledger를 읽어 매수 대기, 체결, 보유, 익절 또는 기간 말 미청산 상태를 표시한다.
매수·매도 Marker도 동일한 날짜의 Ledger를 사용한다. 체결가, 수량, 현금, 총자산, 목표가와
보유기간·손익은 Engine 결과를 재계산하지 않고 표시한다. 매수 미체결 가격 차이는 서버의
presentation adapter가 Ledger의 지정가와 당일 저가로 준비한다. 차트가 시뮬레이션 기간 밖에
있으면 전략 결과가 없음을 표시한다. 이 영역은 차트 위에 겹치지 않으며 Hover 이동마다
서버 요청을 보내지 않는다.

최소 순수익은 수수료·세금 차감 후 확보하고 싶은 수익률을 평가하기 위한 **역산 기준**이다.
필요 매도가와 완료 거래의 충족 여부에 반영하지만, 현재 +5% 익절 주문을 변경하지 않는다.
따라서 이 값만 바꾸면 최종자산·거래횟수는 같아야 하며 필요 매도가가 변해야 한다.

## 뉴스/연구 경계와 장애 처리

뉴스는 로컬 `official_context_catalog.json`에 담긴 공식 발표 4건의 검증용 표본이다. 전체 뉴스
검색이 아니며 0건을 사건 부재로 해석하지 않는다. 기본 연구기간은 현재 실행된 시뮬레이션의 실제
관측기간이다. 사용자는 직접 연구기간을 입력하거나 차트 조회 범위·복기 날짜를 가져올 수 있으며,
화면에 어느 출처의 기간인지 표시한다. 뉴스 조회는 현재 run ID의 전략 요약과 선택 기간의 가격,
공개시각 기준으로 Research Snapshot을 만든다.

복기 모드는 선택 종료일의 KRX 장 마감까지 공개된 자료만 포함한다. 사후 분석은 이후 회고 자료를
별도로 표시한다. 뉴스는 맥락이며 가격의 원인으로 자동 판정하지 않는다. 공급자 오류·네트워크 실패는
사용자가 이해할 수 있는 메시지로 표시하고 시뮬레이션·차트·Ledger의 결과를 유지한다.
검증방 프롬프트는 대상, 기간, 가격, 전략, 거래, 뉴스, 가설과 반증 질문을 포함한다. 개념방용
프롬프트는 별도로 선택한다. 복사·Markdown/JSON 저장은 사용자가 직접 실행한다.

## 향후 AccountProfile 및 자산 적합성 가설

장기 목표는 `Asset-Agnostic Engine + Account-Aware Constraints`다. 계좌 제약과 세제는
`AccountProfile` 정책에서 소유하고 generic Engine에는 계좌명을 하드코딩하지 않는다. 현재는
연금저축·중개형 ISA·일반계좌를 표시하거나 세금을 계산하는 기능을 구현하지 않았다.

다음은 결론이 아닌 반증 가능한 연구 가설이다.

- **H1:** 지수형 ETF는 개별주식보다 변동성이 낮아 +5% 익절 전략의 평균 보유기간이 길 수 있다.
- **H2:** 지수형 ETF는 장기 적립·Buy & Hold가 반복 익절보다 상대적으로 유리할 수 있다.
- **H3:** 개별주식은 변동성이 높아 동일 +5% 익절 전략의 회전율이 높을 수 있다.
- **H4:** 동일 자산이라도 정기 적립·일시금·반복 익절의 상대 성과는 시장 레짐에 따라 달라질 수 있다.

H1~H4는 결론이 아닌 반증 가능한 연구 가설이다. 정기 적립 결과는 외부 현금 유입을
포함하므로 단순 누적 수익률만으로 일시금 또는 익절 전략과 우열을 판단하지 않는다.
XIRR·Money-Weighted Return·Time-Weighted Return은 후속 비교 지표다.

향후 동일 규칙을 TIGER, 국내 개별주식, BTC 등에서 비교할 때 기간·수수료·통화·데이터 품질을
가능한 한 맞추고 Final Portfolio, Net Return, 완료 거래수, 평균/중앙/최대 보유기간,
자본회전율, 거래당 평균 순이익, 총비용, MDD, 미청산 비율을 기록한다. 실제 삼성전자/BTC 수집,
파라미터 탐색, 계좌 세금 엔진은 이번 안정화 범위가 아니다.

## 재현 시나리오와 한계

2023-01-04~2023-04-04, 500,000원, 시가 −1% 매수, 매수가 +5% 익절, 최소 순수익 +1%다.
실제 62거래일 관측에서 최종자산 546,779원, 완료 거래 1건, 기간 말 미청산 1건이다.
이는 특정 표본의 설명용 결과이며 전략 우월성·예측성을 뜻하지 않는다. 비용은 매수·매도 각
0.015%, 세금 0%의 연구 가정이다. 수정주가가 아닌 가격, 분배금 제외, 시가 관측 후 일봉 주문,
intraday 순서 불명 시 보수적 보유 등의 제한은 기존 Simulator 문서를 따른다.
