# STEP 11.1 — Forward observation and evidence lifecycle

The frozen STEP 11 plan remains authoritative. This module records descriptive research evidence, never a trading signal. It uses the existing six-asset provider parsers, FRED macro snapshots, Gate calendar, market-close mapping, STEP 9 price/random metrics, and PRICE_PHASE_V1. SP500 remains a close-only price index; its Phase fields are null. Market-context availability uses the existing conservative per-market release lags and maximum ages.

## Runtime contract

- `scripts/run_forward_validation.py` with no arguments or `--dry-run` validates the frozen protocol and reads only the Git reference Registry. It creates no DB or evidence.
- `--ingest` fetches completed bars for 005930, 000660, SP500, NVDA, MSFT and AAPL. Provider response bytes are archived by SHA-256 under ignored `data/raw/forward/` for subsequent runs. Every accepted row carries symbol, observation date, source provider/series, collection timestamp, raw response SHA-256 and normalized row hash. Only dates strictly newer than the historical cutoff **and** per-asset pre-existing snapshot maximum, collected after the preregistration instant, are accepted. The current market date is excluded.
- The SQLite DB under `data/processed/research/forward_runtime/` is Git-ignored. Identical provider/date/value re-fetches are no-ops. Changed values append a new observation revision and a `SOURCE_MUTATION` event; finalization blocks that asset until a specific source correction is accepted with `--correct-source --symbol SYMBOL --date YYYY-MM-DD --reason TEXT`. Prior revisions remain.
- `--finalize` reads accepted rows only. A Gate whose start predates the freeze cannot become a forward window. OPEN windows contain no final metrics. After the next Gate boundary, fewer than three bars, missing equal-length Pre/Post controls or no mature same-year ±45-day random control keep it CLOSED/PENDING_CONTROL. Missing or stale as-of VIX, US10Y, USDKRW or Broad Dollar keeps it PENDING_CONTEXT. Only complete price and context input creates FINALIZED evidence.
- The evidence record includes the tuple key `(research_id, asset, gate, window_start_utc)`, price metrics, Pre/Post/random controls, macro metrics, Gate.Line, quarter, as-of Phase where available, observation revision IDs, input/result hashes, calculation time and optional superseded evidence ID. An identical rerun appends nothing. A changed input requires explicit correction; old evidence stays immutable. The event log records observation, window transitions, source mutation and correction.
- The runner writes only a small ignored runtime `registry_summary.json` projection: forward status, completed-window count, latest end and evidence references. `data/reference/research_registry.json` keeps the frozen 22 WAITING_FOR_DATA records and original STEP 9/10 research results. Runtime summaries are not canonical Git research conclusions.

The provider's daily series may omit a trading session; a sequence of returned bars alone cannot independently prove exchange-calendar completeness. Automatic finalization therefore remains conservative but requires source-quality review before interpreting any future evidence. Source data license/redistribution restrictions still apply. No scheduler, strategy promotion or STEP 12 trading rule is introduced.

At the first 2026-10-24 provider run, 66 rows passed the frozen cutoff/collection/snapshot predicates, but their **market dates precede the preregistration instant**. They are backfilled runtime observations, not completed prospective Gate evidence. The additional full-window-start-after-freeze guard prevents those dates from producing a final window. A future protocol revision may require every market observation date to follow the preregistration date; that would be a prospective rule change, not a retrospective rewrite of this frozen plan.

The first 66 records captured their raw-response hashes before response-byte archiving was added. A repeated fetch recovered matching raw bytes for 005930, 000660 and SP500. The raw response hashes for NVDA, MSFT and AAPL differed on re-fetch, so exact original response bytes for their first 33 rows remain unavailable. Subsequent ingestions archive bytes append-only. The first US batch therefore has a provenance audit limitation despite its normalized rows and hashes.
