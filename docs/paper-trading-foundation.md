# Paper Trading Foundation — 설계 경계

이 문서는 최초 계약이다. STEP 5에서는 [Paper Trading MVP 구현·실행 계약](paper-trading-mvp.md)에 따라 **S1 단일 자산 SQLite/CLI**를 별도 패키지에 추가했다. 기존 `paper_contract.py`는 미래 확장용 데이터 계약으로 유지하며 현 저장소의 테이블 객체를 그대로 뜻하지 않는다.

- 매일 새로 확정된 관측 데이터만 받아 `Signal → Decision → Order → Execution → Journal`을 순서대로 기록한다.
- Journal은 append-only다. STEP 5 저장소는 중복 `event_id`를 unique 제약으로 거부하고, 일별 실행 API는 다음 관측일만 처리한다. 계좌·이벤트 UPDATE/DELETE는 SQLite 트리거로 거부한다.
- 각 이벤트는 전략 ID·버전, 진입·익절 조건, 설정 해시, 비용 모델 버전, 체결 규칙 버전,
  데이터 공급자·관측시각·원천 데이터 해시를 함께 보존한다.
- S1 계약상 진입 지정가는 당일 시가 × (1+진입 %)를 호가단위로 내림하고 저가가 닿으면 지정가에 체결한다.
  기존 포지션의 익절은 고가가 목표가에 닿으면 목표가에 체결한다. 갭 상승해도 시가 개선체결은
  인정하지 않는다. 같은 날 신규 매수 후 고가가 목표가에 닿은 경우에는 고가·저가 순서를 알 수 없어
  익절을 인정하지 않는다. 이는 현재 백테스트 규칙이며 향후 Paper 기록에서도 버전으로 고정한다.
- 전략 설정이 바뀌어도 이미 기록된 의사결정과 계좌 상태는 다시 계산하거나 덮어쓰지 않는다.
- 실제 증권 주문, 실계좌 연결, 자동 종목 선택은 범위 밖이다. 첫 모의투자 종목은 롤링 검증 결과를 검토한 뒤 사람이 정한다.

후보 검토 체크리스트: ISA 가능, 현재 시드로 1주 이상 매수 가능, rolling 6M·1Y 검토,
동일 창 S0 대비 성과 검토, 최악 창 손실 감당 가능, 최대 자금 고착기간 감당 가능.
체크리스트 통과는 자동 승인이나 실제 매수 신호가 아니다.

새 패키지는 이 계약의 최소 저장·재시작·일별 검증을 제공한다. 실제 새 데이터의 지속 수집, 과거 정정의 경제적 영향 처리, 다중 전략·다중 자산·화면은 후속 과제다. `HISTORICAL_REPLAY`의 재생 성과를 `LIVE_FORWARD`로 표시하지 않는다.
